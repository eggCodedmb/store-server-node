# Docker Compose 本地部署计划

## 目标

将 store-admin-vue（前端）和 store-server-node（后端）通过 docker-compose 部署到本地 Docker 环境，包含 MySQL、Redis、Nginx、Node.js 四个服务。

## 架构总览

```
E:\Code\
├── docker-compose.yml              ← 新建，入口
├── store-server-node/
│   ├── Dockerfile                  ← 修改（修复端口/基础镜像）
│   └── .env.docker                 ← 新建，Docker 环境变量
└── store-admin-vue/
    ├── Dockerfile                  ← 新建，Nginx 托管静态文件
    ├── nginx.conf                  ← 新建，Nginx 反向代理配置
    └── dist/                       ← 已有构建产物，直接使用
```

**4 个服务：**
| 服务 | 镜像 | 端口映射 | 说明 |
|---|---|---|---|
| mysql | mysql:5.7 | 3306:3306 | 数据库，数据通过 volume 持久化 |
| redis | redis:7-alpine | 6379:6379 | 缓存/会话 |
| backend | 自建 (node:18) | 8800:8800 | Koa2 后端 API |
| frontend | 自建 (nginx:alpine) | 80:80 | 前端静态文件 + API 反向代理 |

**请求流向：** 浏览器 → localhost:80 (Nginx) → 静态文件直接返回 / API 转发到 backend:8800

## 需要创建/修改的文件

### 1. 新建 `E:\Code\docker-compose.yml`

定义四个服务及其依赖关系：

```yaml
services:
  mysql:
    image: mysql:5.7
    environment:
      MYSQL_ROOT_PASSWORD: "123456"
      MYSQL_DATABASE: store
    volumes:
      - mysql_data:/var/lib/mysql
    ports:
      - "3306:3306"
    healthcheck: # 等待 MySQL 就绪
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 10s
      retries: 5

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data

  backend:
    build:
      context: ./store-server-node
      dockerfile: Dockerfile
    ports:
      - "8800:8800"
    environment:
      - NODE_ENV=production
      # 所有环境变量通过 .env.docker 文件传入
    env_file:
      - ./store-server-node/.env.docker
    depends_on:
      mysql:
        condition: service_healthy
      redis:
        condition: service_started
    volumes:
      # 上传文件持久化
      - upload_data:/usr/src/app/src/public/online
      # 备份数据持久化
      - backup_data:/usr/src/app/备份

  frontend:
    build:
      context: ./store-admin-vue
      dockerfile: Dockerfile
    ports:
      - "80:80"
    depends_on:
      - backend
```

### 3. 修改 `E:\Code\store-server-node\Dockerfile`

修复现有问题：

```dockerfile
FROM node:18-alpine
WORKDIR /usr/src/app
COPY package*.json ./
RUN npm install --production
COPY . .
EXPOSE 8800
CMD ["node", "src/main.js"]
```

**改动点：**
- EXPOSE 从 5000 改为 8800（匹配实际端口）
- 基础镜像改为 `node:18-alpine`（更小）
- 添加 `--production` 只装生产依赖
- 启动命令简化

### 4. 新建 `E:\Code\store-admin-vue\Dockerfile`

```dockerfile
FROM nginx:alpine
COPY nginx.conf /etc/nginx/conf.d/default.conf
COPY dist /usr/share/nginx/html
EXPOSE 80
```

### 5. 新建 `E:\Code\store-admin-vue\nginx.conf`

```nginx
server {
    listen 80;
    server_name localhost;
    root /usr/share/nginx/html;
    index index.html;

    # 前端路由（Hash 模式，无需 try_files）

    # API 反向代理 - 所有 / 开头的请求转到后端
    location / {
        # 如果是静态文件（带后缀名），直接返回
        if ($request_filename ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf|eot)$) {
            break;
        }
        proxy_pass http://backend:8800;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # 上传文件大小限制
    client_max_body_size 10m;
}
```

**注意：** 由于前端使用 Hash 路由（`createWebHashHistory`），所有页面 URL 都带有 `#`，Nginx 不需要 SPA fallback 配置。API 请求路径如 `/user/login`、`/goods/list` 等都不带文件后缀，会被代理到后端。

### 6. 修改 `E:\Code\store-admin-vue\src\utils\request.js`

将 `baseURL` 从硬编码的绝对地址改为空字符串（同源请求）：

```js
export const baseURL = "";
```

这样 Axios 请求会走当前页面的 origin（即 localhost:80），由 Nginx 代理到后端。

## 验证方式

1. 启动：`docker-compose up -d --build`
2. 检查状态：`docker-compose ps`（四个服务都应 running）
3. 检查日志：`docker-compose logs backend`（应看到 "Mysql连接成功"）
4. 浏览器访问 `http://localhost`（前端页面加载）
5. 浏览器访问 `http://localhost/user/login`（API 返回 JSON 响应）
6. 数据库初始化：进入 backend 容器运行 seed 脚本（首次启动时）

```bash
docker-compose exec backend node src/db/seedRbacEntity.js
docker-compose exec backend node src/db/seedBusinessData.js
```
